# Сторож CODE Eternal — внешняя проверка живости

## Статус: развёрнут и проверен (26.07.2026)

Адрес: **https://aifa-watchdog.codeeternal.workers.dev**
Расписание: каждые 5 минут (Cron Trigger Cloudflare, бесплатно).

## Зачем он нужен, если оповещения уже есть

Два прежних слоя оба неполны:

1. **Внутренние письма** (`lib/alert.ts` на сайтах) живут внутри самих сайтов.
   Если сайт лёг целиком или недоступен Vercel — отправлять письмо уже некому.
2. **UptimeRobot** следит за тремя сайтами и не покрывает radiocode.space и
   телеграм-бота. На бесплатном тарифе их API не позволяет заводить проверки —
   только руками в их интерфейсе.

Этот сторож стоит снаружи, в сети Cloudflare, и покрывает **все пять** сервисов.

## Что именно проверяется

Не «отвечает ли страница» — сайт может отдавать 200 с мёртвой базой, и человек
это увидит, а обычный монитор нет. Проверяется содержимое пробы здоровья:

| Цель | Адрес | Признак жизни |
|---|---|---|
| codeofdigitaleternity.com | `/api/health` | `"db":true` |
| aifa.digital | `/api/health` | `"db":true` |
| aifa.works | `/api/health` | `"db":true` |
| radiocode.space | `/api/health` | `"db":true` |
| Телеграм-бот (Cloud Run) | `/readyz` | `"ready":true` |

⚠️ У бота именно `/readyz`: путь `/healthz` перехватывает сам Cloud Run и
отдаёт свою страницу 404, до приложения запрос не доходит. На это уже
наступили — сторож нашёл это в первый же запуск.

## Оповещение

Письмо владельцу через Resend. Повтор той же беды гасится на час: отметка
кладётся в кэш края сети, поэтому своего хранилища сторожу не нужно.

Проверено вживую 26.07.2026: учебная тревога → «письмо отправлено», повторный
вызов → «придержано». Тестовая копия воркера после проверки удалена.

## Ручная проверка

```bash
curl https://aifa-watchdog.codeeternal.workers.dev/check
```
Показывает текущее состояние всех целей. Письмо при этом НЕ шлётся — чтобы
проверка не будила почтой.

## Развёртывание

Токен — в `ТОКЕНЫ и API…/CLOUDFLARE_API_TOKEN.txt`.

```bash
cd D:/CODE/radiocode-space/infra/watchdog-worker
CLOUDFLARE_API_TOKEN=<токен> npx wrangler deploy
```

Секреты (задаются один раз, в репозитории их нет):
`RESEND_API_KEY`, `RESEND_FROM`.
